# Admin / PBS Portal 登录凭据串填回归测试

## 前置条件

- 使用独立的干净 Chrome profile，禁用第三方密码管理扩展，并记录 Chrome 版本。
- 开启 Chrome 密码保存及自动登录/自动填充功能。
- Admin 与 PBS Portal 使用同一 SIT 域名、不同路径。
- 在 Chrome Password Manager 中确认已保存 Portal 账号 A 和 Admin 账号 B。

## 主流程

1. 使用已保存账号 A 登录 Portal 后登出。
2. 使用已保存账号 B 登录 Admin 后登出。
3. 重新打开 Portal 登录页，不操作输入框并等待至少 2 秒。
4. 确认 User Code 和 Password 均为空。
5. 重新打开 Admin 登录页，不操作输入框并等待至少 2 秒。
6. 确认 User Name 和 Password 均为空。
7. 分别在两个页面主动点击账号与密码字段并手动输入，等待至少 2 秒。
8. 确认输入值未被清理，并能正常登录。

## 边界场景

- 通过浏览器前进/后退返回登录页时，未提交凭据应被清空。
- 刷新登录页后，账号和密码应为空。
- 仅用 Tab 聚焦字段不会解除保护；输入首个字符时应正常解锁且字符不能丢失。
- 用户名字段按 Enter 跳到密码字段后，密码仍为空；输入首个密码字符不能丢失。
- 浏览器可以显示密码候选列表；不主动选择候选项时，不得静默写入字段。
- Admin 密码显示/隐藏、Portal 密码显示/隐藏及 SSO Login 不受影响。

## 预期结果

- Admin 与 Portal 均不保存或恢复应用层用户名、密码。
- 两个登录页在用户主动操作前保持空白，不发生同域路径之间的凭据串填。
- 用户主动输入及原有认证流程正常。
