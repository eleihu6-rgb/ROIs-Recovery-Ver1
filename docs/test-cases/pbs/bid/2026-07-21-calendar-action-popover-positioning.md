# PBS Bid 日历操作弹层防裁切测试案例

## 1. 测试目标

验证 `BIDDING CALENDAR` 的 Days Off / Pairing 操作弹层在不同日期行、桌面窗口高度和画布缩放比例下完整显示，不被左侧卡片裁切，也不引入页面或左侧日历整体滚动。

## 2. 前置条件

- 使用存在当前 bid period 的测试账号登录 PBS Portal。
- 当前 bid period 至少包含一个可点击日期。
- Pairing tab 能正常加载该日期的 pairing occurrence；无数据、loading 和 error 状态也需要执行边界检查。
- 浏览器缩放保持 100%。

## 3. 标准桌面视口

### 操作步骤

1. 将浏览器视口设置为 `1920 × 1080`。
2. 进入 `Bid` 页面。
3. 在左侧 `BIDDING CALENDAR` 点击第一周的可用日期。
4. 在弹层中选择 `PAIRING`。
5. 检查弹层标题、日期、Pairing Numbers、搜索框、occurrence 列表、`APPLY TO TIERS · REQUIRED`、`Cancel` 和 `ADD BID`。

### 预期结果

- 弹层根据可用空间向上或向下展开。
- 弹层顶部和底部均位于左侧日历卡片可视区域内。
- Tier 选项、`Cancel` 和 `ADD BID` 完整可见且可操作。
- 弹层右边缘不进入右侧 Bid 工作区。
- 页面和左侧日历不出现整体滚动条。

## 4. 较矮桌面视口

### 操作步骤

1. 保持弹层打开，将视口设置为 `1366 × 700`。
2. 检查弹层位置和全部固定操作区。
3. 当 occurrence 数量超过列表可视高度时，在 occurrence 列表内滚动。

### 预期结果

- 窗口尺寸变化后弹层自动重新定位。
- 标题、日期、Tier 和底部操作按钮不会被压缩或裁切。
- 只有 occurrence 列表内部滚动；页面和左侧日历仍不滚动。

## 5. 日期行与横向边界

### 操作步骤

1. 分别点击第一周、中间周和最后一周的可用日期。
2. 分别点击最左列和最右列日期。
3. 每次打开 Days Off 和 Pairing 两种模式。

### 预期结果

- 下方空间不足时弹层自动向上展开，上方不足时自动向下展开。
- 弹层始终限制在左侧日历的左右边界内。
- 切换 Days Off / Pairing 后，内容高度变化不会使弹层越界。

## 6. 状态与交互回归

### 操作步骤

1. 覆盖 Pairing loading、空结果、加载失败和保存失败状态。
2. 点击弹层外空白区域。
3. 在保存进行中再次点击空白区域、`Cancel`、`Clear`、搜索和选项。

### 预期结果

- 各状态高度变化后弹层重新定位并保持完整可见。
- 非保存状态点击空白区域可关闭弹层。
- 保存进行中保持现有禁用规则，不能通过空白区域或禁用控件中断保存。
- 保存、取消、Tier 多选和 occurrence 多选业务行为无回归。

## 7. 回归范围

- Bid、Days Off 和 Pairing 页面共享的 `BIDDING CALENDAR`。
- 左侧日历展开/收起动画。
- Days Off / Pairing 双模式日期入口。
- 画布缩放与固定视口布局。
- Pairing occurrence 内部滚动。
