# Pairing Preference 结果刷新回顶与骨架屏回归用例

## 前置条件

- 当前投标周期至少存在两页可选 Pairing。
- 第一页 Pairing 行数足以让列表区域出现垂直滚动条。
- 打开 `Configure Pairing Preference` 弹窗。

## 操作步骤

1. 将 Pairing 列表滚动到第一页底部并点击下一页。
2. 等待第二页返回，再输入新的关键词。
3. 打开筛选栏，修改有效条件并点击 `Apply filters`。
4. 在筛选条件非空时点击 `Clear filters`。
5. 分别在四种请求尚未完成时观察列表、分页按钮和页码。

## 预期结果

- 分页、关键词 debounce 搜索、应用筛选和清除筛选导致查询条件实际变化时，Pairing 列表均立即回到顶部。
- 四种请求期间均不显示旧数据，改为显示保留表头和列表高度的 7 行表格骨架屏。
- 请求期间列表具有可访问的忙碌状态，上一页和下一页按钮均不可点击。
- 分页时页码立即显示目标页，例如 `Page 2 of 2`；搜索和筛选时回到第一页。
- 请求完成后骨架屏消失并显示新结果，列表滚动位置仍为顶部。
- 跨页选择保持不变；切回上一页后已选状态仍正确。

## 异常与边界场景

- 分页请求失败时显示现有 `Unable to load pairings` 和 `Retry`，不得重新把旧页数据当作目标页展示。
- 校验失败、重复应用相同筛选、空条件重复清除不显示骨架屏，也不重置滚动位置。
- 普通后台刷新沿用原有刷新行为，不应被误判为结果条件变化。
- 加载期间连续点击分页按钮不会发出额外翻页请求。

## 回归范围

- Pairing Preference 搜索、筛选、跨页选择。
- Standing Bid 中复用 Pairing Preference 的配置入口。
- Pairing Search 独立页面的分页与骨架屏不受影响。
