Crew app / offline snapshot / design review Ver1

The last roster you loaded should open instantly.

A cache-first crew session for PR and TG: one portal login creates a local data pack, the app opens from it without waiting for the network, and every refresh stays explicit. This mockup covers every UI surface affected by the design, including the read-only offline states, the re-login path, and the development-only Offline Lab.

The reading path

One pack, four moments.

The UI is intentionally quiet when the copy is fresh. The status language only appears when the crew needs to make a decision: the copy is old, the app is offline, a refresh failed, or there is no cached result for the current Duty Swap search.

1. First login

Portal authentication succeeds. The app saves the session, then captures the roster. The first capture can still block, but a failed capture no longer forces the password to be entered again.

  • Capture progress shows the crew ID and the saved-session state.
  • Failure keeps the existing pack and offers Retry capture.

2. Next launch

The app restores Keychain identity and reads the pack. The main tabs render from local data. No portal spinner, no WebView, no network dependency.

  • Fresh data shows a small timestamp, not a banner.
  • Offline or stale data shows a compact banner.

3. Refresh

The crew taps Refresh latest. The current pack stays on screen until the new capture is validated and committed. A timeout leaves the old copy intact.

  • Success replaces the pack and clears the previous error.
  • Partial or empty results require confirmation before replacing a good pack.

4. Re-login

Use Re-login when the portal rejects the stored session or the password changed. The app validates once, never loops, and keeps the old pack if authentication fails.

  • Refresh reuses the token when possible.
  • Re-login always discards the token first.
Profile / Data & Sync

The control room for the local copy.

One new section below Preferences. It shows the signed-in crew, the last successful update, what is stored locally, and the two explicit recovery actions. Offline is a toggle, not a hidden mode.

Agenda / My Trips

Show the copy, not a spinner.

The existing refresh icon stays. The new layer is a compact status line under the header when the copy is old or a refresh failed. When the copy is fresh, the timestamp is quiet and there is no banner.

Duty Swap / PR only

Read the saved market. Never fake a send.

The existing Matrix layout stays. The new layer is a read-only banner, a timestamp in the search strip, and disabled write actions. Changing the date window or filters while offline does not reuse the old result as if it matched.

Recovery dialogs

Recover without losing the copy.

Re-login is a single validation attempt. Clear offline copy is destructive and uses the standard Status-Card dialog: carrier-colour header band, semantic tone on the glyph and primary pill.

Failure and confirmation states

When the portal disagrees, the copy stays.

These are the four states that protect the last good copy: a rejected password, a partial roster, an empty roster, and an unreadable pack. None of them silently replaces usable data.

First login / capture

Save the login before the roster.

The login page gains one helper line; the capture flow gains a clear separation between "signed in" and "roster updated". If the WebView times out, the crew stays signed in and can retry without re-entering the password. A saved pack, if one exists, remains available.

Developer tools / not shipped

Switch PR and TG in seconds.

The Offline Lab is a development-only route gated by __DEV__ plus an explicit flag. It lists local packs, shows their age and counts, and can open one without a portal request. This is the testing accelerator; it does not change production account isolation.

Copy deck

Short, factual, and never ambiguous.

The copy avoids "syncing forever" language. It says what is stored, when it was stored, and what is blocked. Timestamps use the same local format everywhere.

State rules

  • Fresh: no banner, small timestamp only.
  • Stale: amber banner with age and Refresh.
  • Offline: amber banner, read-only actions, Work offline on.
  • Failed: red banner with Retry, last good copy still visible.
  • Missing search: neutral info state, no fabricated rows.

Guardrails

  • No portal token, password, or raw payload in the pack.
  • Identity mismatch never renders; late responses never write.
  • Refresh and re-login are single-flight and single-attempt.
  • Duty Swap writes are unavailable offline.
  • Offline Lab and fixtures are dev-only.

Implementation note

This is a design artifact only. The implementation should reuse the existing AppDialog, carrier tokens, outline icon set, one-row header behavior, and existing Duty Swap Matrix.
