## 1. 双 Roster Pane（主副屏）

**Q1.1** 两个 Roster Pane 是否完全独立？（各自独立筛选、独立排序、独立滚动）

**回答：是的，独立筛选、独立排序、独立滚动，可以将任务从主Pane 拖动到副Pane上，或者直接在主Pane从一个Crew拖动到另一个Crew


**Q1.2** 在两个 Pane 之间拖拽任务，是 move（移动到另一个 crew）操作还是 swap（互换）操作？还是两者都支持？

**回答：两者都支持，拖拽任务到副Pane上，任务将自动从主Pane中删除，并且任务将自动添加到副Pane中。也可以主Pane内不同的Crew也能拖拽任务，交换任务


**Q1.3** 是否支持从 Pairing Pane 拖拽 pairing 到 Roster Pane 给某个 crew 分配任务？

**回答：是的，支持从Pairing Pane 拖拽任务到 Roster Pane


**Q1.4** 是否支持从 Flight Pane 拖拽航班到 Roster Pane？

**回答：当然，能拖拽到Roster Pane ，也是组在一个Pairing 里面，也可以直接将航班拖拽到Pairing Pane，对应的Roster Pane 的Pairing 数据也会跟着一起变化


**Q1.5** 主副屏是固定的上下布局，还是用户可以自由调整（左右/上下/浮动）？

**回答：可以自由上下调整显示或隐藏，左右不用支持，浮动能支持更好

## 2. 顶部红色汇总条

**Q2.1** 红色汇总条显示的是什么数据？（每天的人力缺口？需求 vs 已排人数？）

**回答：统计区域，配置需要统计的任务组，然后将这一天内，所有Crew 执行过改任务的人数进行统计，或者统计未排任务的人数。


**Q2.2** 点击红色汇总条的某一天，是否有交互效果？（如跳转、筛选、弹窗？）

**回答：有弹窗，弹窗内容，为一个树形菜单统计内容，第一个Root 节点为Crew 所有Crew信息，展开后，底下按Rank 分层，统计每个Rank有多少人
    第二个Root 节点为Assignment 任务数量统计，和颜色区域统计数据一致


**Q2.3** 汇总条是按 rank 分层显示，还是总体汇总？

**回答：颜色区域是按任务类型统计，这一天，执行这个任务类型的人数，每种任务类型所占百分比，计算出高度

**Q3.4** 多个 Pane 同时显示时的布局方式？（上下堆叠？可拖拽调整大小？）

## 4. 左侧 Crew 固定列

**Q4.1** Roster Pane 左侧固定列具体显示哪些字段？（截图中看到有 Rank、MCC，还有其他吗？）

**回答：左侧为CrewId，CrewName，CrewBase，Crew Rank，Crew Fleet，Seniority YBH/MBH/YAL/MAL/YDO/MDO 等，可以自定义每一列的宽度，显示顺序，分为上下两行，以及是否显示等


**Q4.2** 左侧列是否可以由用户自定义显示/隐藏？

**回答：可以


**Q4.3** 左侧列是否支持点击排序？（如按 Rank 排序、按 Crew ID 排序）

**回答：需要，点击排序后，在工具条上出现，目前按什么字段排序，以及排序顺序，界面打开时，默认按什么字段排序，需要可以自定义，因为有的航司默认按CrewId，有的需要按CrewRank排序


**Q4.4** Pairing Pane 左侧固定列显示哪些字段？

**回答：左侧显示Pairing 的机型，飞时，以及当前Pairing 配比，配比满配时，括号内只显示一个数字，例如：FCN(1)FFO(1) 当有配比不满时，需要显示Plan:Fill 例如： FCN(1:0)FFO(1:0) 不满的Fill值需要以红色字体显示


**Q4.5** Flight Pane 左侧固定列显示哪些字段？

**回答：机尾号，机型

## 9. 业务流程

**Q9.1** 排班员打开系统后的典型操作流程是什么？（步骤1→步骤2→...）

**回答：打开Gantt后，可能会找组员调整班表，也可能从Pairing 找未排满的Pairing，分给其他人，以及找航班未排满，进行建环等常规操作，所以系统很重要的一个功能是查询与筛选一定要准确


**Q9.2** 在 Gantt 上修改排班后，法规检查是即时触发还是需要手动点击？

**回答：只要在Gantt 上做了任务修改，都需要触发法规检查，如有告警，需要显示在任务或左边Header上


**Q9.3** 法规检查不通过时，是否允许强制保存？还是必须修正后才能保存？

**回答：根据法规告警层度来定，如果是不可违反法规级别，就应该阻止本次修改操作，如果是可以违反的法规级别，就可以继续进行修改操作，只要修改过的任务，后续都应该可以保存，Gantt界面还需要支持undo与redo功能


**Q9.4** 排班发布的流程是什么？需要审批吗？

**回答：排班发布流程分计划发布和动态实时发布，例如一家航司按月发布下个月的排班计划，一般会在每个月的20号公布下个月的排班计划，在20号这一天发布下个月计划时叫计划发布。
除了计划发布之外，还有动态实时发布，假如当前时间是4.1号，当用户操作的班表是在4.1-4.30本月之类，那么这些班表实际上是在3.20号已经计划发布过了，动4.1-4.30周期的班表，
可以动态发布功能，找出哪些班表是被实时调整过，调整过的班表通过动态发布之后，组员就能看到新的版本，在未动态发布之前，还是看到的3.20号发布的那一版数据结果
