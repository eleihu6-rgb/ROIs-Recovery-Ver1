Gantt English Date Picker Mockup

Goal: replace the browser-native date input with a controlled English picker so the toolbar and popup never depend on operating-system locale. The Gantt planning values still store and parse calendar dates as YYYY-MM-DD.

~

A. Two English Date Buttons

Recommended
Toolbar control
~
  • Most similar to the current start/end field layout.
  • Each button opens the same custom English calendar.
  • Keeps keyboard editing possible through a small text field inside the popup.
  • Best fit for a dense operations toolbar.

B. One Range Button

Toolbar control
  • Consumes less toolbar width than two full dates.
  • Good if start/end are usually changed together.
  • Less direct when planners only need to change one side.
  • Requires a more complex range-selection popup.

C. Compact Month-Day Buttons

Toolbar control
~
  • Very compact for narrow screens.
  • Year appears in tooltip and popup header.
  • Can be ambiguous across year boundaries.
  • Better as a responsive fallback than the primary desktop display.

Behavior Contract

  • No native input type="date" UI.
  • Visible labels use English month and weekday names.
  • Parsing still accepts YYYY-MM-DD for precision and automation.
  • Timezone behavior stays identical to the current Gantt date range picker.
  • Existing three-month planning-window constraint remains enforced.

Testing Notes

  • Playwright should assert toolbar labels such as Jul 1, 2026.
  • Run the same test with browser locale changed to prove labels stay English.
  • Verify changing start/end reloads panes through the existing auto-apply path.
  • Run npm run check:ui after implementation style changes.
Recommended direction: use option A for desktop and keep option C as a responsive fallback below the toolbar's narrow breakpoint. This avoids the browser-native calendar entirely while preserving the current two-field mental model.
