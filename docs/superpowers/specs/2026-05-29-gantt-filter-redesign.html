Gantt Filter System — Design Spec
2026-05-29 · Three-tier filter dialog + per-pane quick filter
Architecture Overview
Filters are divided into two scopes. Global filters (in GanttSubToolbar) control which data rows are loaded from the API — crew rows in Roster, pairings in Pairing pane, flights in Flight pane. Per-pane filters are additional quick filters local to each pane (sort, text search, status chips) that do not trigger a refetch.

Per-Pane Filter — Inline Quick Filter
Each pane's toolbar has a Filter button that expands a compact quick-filter panel below. Active filter chips appear inline in Row 1, to the right of the loaded-count badge, each with an × to dismiss. Per-pane filters are client-side only (no API refetch) and are pane-local (not shared with other panes). No sort controls.

Implementation Notes
FilterStore restructure — current flat fields (ranks[], crewBases[]…) are reorganised into three namespaced objects: crew, pairing, flight. This enables clear API mapping and tab-level reset without touching other tiers.
Reference data cache — a new useReferenceStore fetches GET /api/base, GET /api/rank, GET /api/fleet once on app init (or lazy on first filter open) and caches them for all dropdowns. No per-open refetch.
MultiSelectDropdown component — shared between all three tiers. Props: options: {value, label}[], value: string[], onChange, placeholder, color. Renders a searchable checkbox list popover. Built once, used in all filter rows.
Per-pane vs global scope — Global filter triggers gantt-view-store.refreshAllPanes() (API refetch). Per-pane quick filter is pure client-side: filters the already-loaded data array in the pane store, no API call. No sort controls — sorting is handled by the Gantt canvas row ordering. This keeps quick interactions fast.
Inline chip wiring — Active per-pane filter values are rendered as pt-qchip elements inline in PaneToolbar Row 1, immediately after the loaded-count (↓) badge. Each chip has an × button that clears only that field. When no chips are active, the space collapses to zero width. No separate Row 2 strip — the existing filterChips / Row 2 design in PaneToolbar is replaced by this inline approach.
Existing code reused — PaneToolbar filterChips props are already wired (not called yet). CrewFilter and layout Sidebar components are deprecated in favour of the new global dialog. The unused sidebar.tsx + crew-filter.tsx can be deleted.
