Schedule ▸ Route map — flight info on the map

A local mock for the Duo inner screen route view. Each destination's code, distance and leg count is printed beside its endpoint instead of living only in the Routes list. The label is placed away from the great-circle arc, carries an automatic clearance check against every route line and against the stats / zoom / base chrome, and takes its ink and glass from the map tokens of the active carrier theme — never a fixed black badge. Requirements met

  1. Blends into the map — map tokens plus a low-alpha carrier tint; no fixed black badge.
  2. Route line stays clear — every label is scored against all sampled arcs; the winner sits outside the tangent with a leader tick.
  3. Colour per theme — Reference blue, Thai violet, Emerald, Graphite and Daylight each recolour the land, glass and ink.
  4. Local mock first — this page is the pre-dev artefact; the landing notes below map it onto RouteMapView.tsx.

1 · Blend into the map

  • No fixed black slab. The old rgba(0,0,0,.45) badges are replaced by --map-glass, a translucent mix of the map ground and a low-alpha tint of the carrier's own g3.
  • Ink comes from the map. Code and meta use --map-label; the leader, markers and focus ring use --map-route.
  • Quiet by default. The glass is 78 % opaque; the map still reads through it. Daylight flips the same recipe to white glass on a light map.

2 · Keep the route line clear

  • Labels are anchored outside the arrival tangent: ten candidate directions around the endpoint, biased away from the base.
  • Every candidate is scored against all sampled great-circle points (penalty when a label rect comes within ~2 px of an arc), against placed labels, and against the base badge / zoom / stats rectangles.
  • The winner gets a 10 px leader tick; the arc itself is never masked. Toggle the clearance switch to see the unmanaged placement.

Content

  • Label line 1: airport code (monthRoutes[].code).
  • Label line 2: distance · legs (formatKm(km) and legs) — the same two values the Routes row already carries, so the map never invents data.
  • Tap a label or a route row to focus the arc; the rest dim to --map-muted.

Dev landing

  • RouteMapView.tsx: add a label layer beside the existing SVG; reuse greatCirclePath sampling, routeViewBox and mercatorX/Y, so geometry stays identical.
  • carrier.ts: add mapGlass, mapGlassFocus, mapGlassLine, mapPanel (already present), and keep mapLabel/mapRoute/mapLand as the only ink sources.
  • Placement is pure geometry — no tile SDK, no native map module, still offline. Same code path for Live/Scenario.

Responsive / fallbacks

  • Duo inner: labels at full size, as shown.
  • Air / Duo outer: if the card is too narrow for both lines, drop the meta line and keep the code; never truncate the code. The clearance search stays on.
  • No coordinates: the destination is still counted in stats and listed in Routes, but draws no label (same as today's no-line behaviour).
  • Selected label gets --map-glass-focus + a 1px --map-focus-ring, no shadow-heavy callout.
