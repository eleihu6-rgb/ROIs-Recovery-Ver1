What changes in the code

  • All three: fontVariant:['tabular-nums'] on the numbers, adjustsFontSizeToFit dropped where the column is wide enough, and the last row’s redundant bottom border removed (today the card ends on a rule).
  • A: StatsCard’s statsRows stack becomes a 3-up flex row inside the same padding:14 box as the totals. No new data — monthStats() already returns routes/airports/countries.
  • B: style-only: statsCell + statsRowLabel/statsRowValue become right-aligned. No JSX change.
  • C: statsGrid becomes a 2-column grid; the 3 counts move into a bar; the map card may drop 12–16 pt to keep the first route row above the dock.
  • A+ (optional, needs your call): add a 4th count — Legs, already computable as the sum of monthRoutes().legs — so both tiers share the identical 4-column grid and the numbers stack in perfect vertical columns. It is a new metric on the card, so it is a product decision, not a layout one.

Notes for whoever implements

That is iOS Larger Text / Dynamic Type, not a different build; I reproduced the same screen on the sim today and it matches the file. The mock uses the file’s numbers. Note the 4-up row still needs adjustsFontSizeToFit for a scaled-up DISTANCE KM column.
