    Multi-Crew Batch Create
    One dialog creates N roster_flight rows — one per selected crew. All rows share the same assignment, time range, and remark. Useful for assigning training or standby to an entire crew group at once.
    Assignment → Group Auto-Fill
    When an assignment is selected, assignment_group is automatically resolved from assignment.default_assignment_group. The field is read-only — planners never need to set it manually.
    Separate Date + Time Inputs
    Date and time are separate inputs to avoid datetime-local browser inconsistencies. Both are UTC. Duration is computed live and shown below the end-time row. End before start shows a warning.
    pairing_id = NULL
    Ground tasks are created with pairing_id = NULL, distinguishing them from flight-linked roster entries. The Gantt renderer already handles this — ground tasks render as a solid bar without pairing decorations.
    Draft Mode Integration
    On submit, the dialog calls roster-store.addTask() which adds an op type: 'add' to the draft. Multi-crew: N ops, one per crew. Undo removes all N at once (they share the same batch ID).

    Crew is Read-Only in Edit Mode
    The crew field is locked — editing crew identity requires delete + create. This prevents accidental reassignment and keeps the audit trail clean.
    Fields Updated via PUT /api/roster/:id
    On save, calls roster-store.updateTask() which emits op type: 'update' in draft mode. Fields sent: assignment, assignmentGroup, schStrDtUtc, schEndDtUtc, comments.
    Delete Ground Task
    The "Danger Zone" delete button triggers a confirmation prompt, then calls op type: 'remove' in draft mode. Ground tasks only — flight tasks use the pairing delete flow.
