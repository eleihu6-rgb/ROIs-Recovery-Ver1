Implementation Approach (Proposed)
① Backend — Crew History API
Extend GET /api/crew/:id/detail (or add batch endpoint) to return full rank / base / fleet history arrays instead of just currentRank.

CrewDetail.rankHistory: CrewRankRecord[]
CrewDetail.baseHistory: CrewBaseRecord[]
CrewDetail.fleetHistory: CrewFleetRecord[]
② Frontend — Derived Values
In roster-pane.tsx, compute effective rank/base/fleet from history arrays using viewportLeftDate:

scrollX → xToTime() → viewportLeftDate

useMemo on [selectedCrewIds, crewDetailMap, viewportLeftDate] — only re-computes when date changes.
③ Canvas — Two-Row with Span
Roster pane already uses drawTwoLineRow(). Set bottomRowKey = 'crewName' so the full name spans the bottom 18px strip.

Move fleet column config from row: 2 → row: 1. Move ybh to row 1 as well.

Crew name value: firstName + (middleName ? " " + middleName : "") + " " + lastName
Open Questions — Need Your Input
1
When viewport date changes (scroll), how should rank/base/fleet update?
ALive — re-compute on every scroll event (fast, all data on frontend from history arrays)
BDebounced — re-compute 300ms after scrolling stops (slight lag, reduces churn)
CManual — only update when a refresh button is clicked (simplest, but not reactive)
2
Where should YBH (and other stat columns) go since crewName now spans the full bottom row?
A ✓Move YBH (and optionally MBH, YAL… when visible) to row 1 alongside rank/base/fleet — total row 1 width: 70+45+45+50+55 = 265px
BKeep YBH in a third-row concept (triple-row layout — new design territory)
CDrop stats from the panel; show on hover only (tooltip)
3
What if a crew has multiple effective rank records at the viewport date (e.g., two overlapping records)?
AShow the most recent (highest eff_dt) — most likely intended behaviour
BShow all concatenated (e.g., "CA / FCN") — for dual-type ratings
CShow the one with position = '1' (primary position)
4
Name display format in the spanning bottom row — which format?
AfirstName + " " + middleName + " " + lastName → "John M. CHAN"
BlastName + ", " + firstName + " " + middleName → "CHAN, John M."
CUse preferredName when available, fall back to firstName
